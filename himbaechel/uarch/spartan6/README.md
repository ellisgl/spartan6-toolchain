# Spartan-6 himbaechel uarch

Place and route for the Xilinx Spartan-6 xc6slx9 (tested on the Mojo V3,
TQG144), built on [prjcombine](https://codeberg.org/prjunnamed/prjcombine)'s
Spartan-6 database.

## Status

- **Devices:** xc6slx9 only (`--device xc6slx9-2tqg144`).
- **Supported:** most of what `synth_xilinx -family xc6s` emits by default:
  LUTs (with LUT6/LUT5 pairing), FFs (including 5FFs), latches (LDCE/LDPE),
  falling-edge FFs/RAM/SRLs (slice clock inversion), CARRY4, MUXF7/MUXF8,
  RAMB16BWER/RAMB8BWER, DSP48A1, distributed RAM (RAM64X1S, RAM32M, RAM64M,
  RAM64X1D, RAM128X1S/D, RAM256X1S), SRLC32E (including Q31 chains) and
  SRL16E, I/O (IBUF/OBUF/OBUFT/IOBUF, LVTTL/LVCMOS33/LVCMOS25,
  PULLUP/PULLDOWN, DRIVE, SLEW), BUFG and the global clock network, DCM_SP
  (CLKFX/CLKFX180, and the DLL outputs with CLK_FEEDBACK = 1X) and
  PLL_BASE/PLL_ADV (INTERNAL; SYSTEM/SOURCE_SYNCHRONOUS with direct
  feedback, which becomes INTERNAL as in ISE's map, or feedback through a
  BUFG, which gets a BUFIO2FB reached through an unused ILOGIC).
- **Not yet:** DSP cascades, SRLs using both Q and Q31, RAM32X1S/D, DCM 2X
  feedback and phase shifting. Global clock
  nets stay on the clock network (pip flag 2). Timing comes from a delay model
  fitted to ISE's timing output (see the
  [xc6slx9-pnr](https://github.com/ellisgl/xc6slx9-pnr) README), within
  about +-9% of ISE's analyser on the test designs.
- **Checked against ISE 14.7:** designs placed and routed here are converted
  to XDL and pass ISE's DRC, and the open bitstream writer's output is
  byte-identical to ISE bitgen's for the same placement and routing. Test
  designs for each feature pass on hardware (Mojo V3).

## Usage

```
yosys -p "synth_xilinx -family xc6s -top top -json synth.json" top.v
nextpnr-himbaechel --device xc6slx9-2tqg144 --chipdb chipdb-xc6slx9.bin \
    --json synth.json -o ucf=top.ucf --write routed.json
```

Options (`-o name=value`):

- `ucf=<file>`: UCF subset: `LOC`, `IOSTANDARD`, `DRIVE`, `SLEW`, `PULLUP`,
  `PULLDOWN` on `NET` statements (`led<0>` matches `led[0]`).
- `nolut5`: don't pair LUTs into shared LUT6/LUT5 sites.

The bitstream is generated from `routed.json` by `s6-bitgen`, which is outside
nextpnr.

## Chip database

The chip database is not generated by this CMake build; the tools that
build it, the bitstream writer (`s6-bitgen`) and the test designs are in
[xc6slx9-pnr](https://github.com/ellisgl/xc6slx9-pnr), whose `make` builds
this nextpnr and the chip database together. It comes from
prjcombine's Spartan-6 database through a Rust exporter (`s6-export`, one
himbaechel tile per prjcombine cell; slices split into sub-bels) and a
`himbaechel_dbgen` script, then `bbasm`. Pass it with `--chipdb`, or install
it as `<share>/himbaechel/spartan6/chipdb-xc6slx9.bin`.

## Slice model

Each slice is split into sub-bels, with the slice's internal muxes as
pseudo-pips:

- per letter A–D: `SLICE_LUT` (LUT6, z+0; LUT5, z+1), `SLICE_FF` (FF, z+2;
  5FF, z+3);
- `SLICE_F7MUX`/`SLICE_F8MUX` and `CARRY4` in SLICEL/SLICEM; SLICEM LUT6
  bels also carry the RAM pins (write address, DI1/DI2, WE, CLK, MC31, O5).

The z layout is `0x100 + 0x40 * slice + 8 * letter + kind` (`spartan6.h`).

- **LUT pairing:** two LUTs with at most 5 distinct inputs between them are
  packed into one LUT6 site as a cluster, sharing A1–A5. The O6 half gets A6
  tied high; the O5 half has cell type `SLICE_LUT5`.
- **5FFs:** a 5FF's D is hardwired to O5 and its Q leaves only through the
  `<L>MUX` pin, so it only takes a FF that is the sole load of a LUT5 half
  (cell type `SLICE_FF5`, in the same cluster).
- **Control sets:** all 8 storage elements of a slice share CLK, CE, SR and
  sync/async mode.
